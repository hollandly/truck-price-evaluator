# 货车二手车 / 租赁价格评估系统

面向 **9.6 米以上车型**（含柴油 / 纯电 / 氢燃料 / 混动）的价格评估工具，支持 **二手车售卖** 与 **车辆租赁** 双模式，多因子定价，并可对标联网抓取的最新市场行情辅助决策。

## 功能特性

- **二手车售卖评估（双轨交叉验证）**：
  - **市场行情法**：采用「同龄二手车实际成交价」作基准，用车况、事故、里程、排放、保养、改装、区域、电池健康度等因子微调。
  - **新车折旧法**（填写新车购买价后启用）：新车价 × 分能源残值率曲线 × 车况因子。残值率依据 2026 调研（柴油3年60%、纯电3年43%、混动3年48%、氢能3年45%）。
  - **综合估值** = 市场法 60% + 新车法 40%，并展示两法差异供判断。填入新车价能让估值更客观，两法接近时可信度更高。
- **租赁评估（区分两种车源）**：
  - **个人车主直租**（低价口径，基准）：如广州 9.6 米 4x2 厢车 3 年内约 **5,500 元/月**（不含司机/油费/维保）。
  - **租赁公司**（含保险/维保/票据/服务）：约为个人车主的 **1.85 倍**。
  - 在此基准上叠加车龄、区域、租期、带司机、保险、尾板、旺季等因子。
- **车型细分**：覆盖 9.6 米单桥(4x2)、双桥(6x2)、前四后八(8x4)、**甩箱车(车厢可卸式)**、13 米牵引、17.5 米大板、49 吨牵引。
- **货箱类型**：厢式、高栏/仓栅、**飞翼厢式**、平板、冷藏、尾板车、自卸，专用车厢带溢价系数。
- **品牌档次**：解放/东风/重汽/福田欧曼/陕汽德龙/江淮柳汽/远程/小众共 8 档，按流通性和保值率设系数。
- **市场对比决策**：评估价 vs 行情区间，给出高/中/低判定与区间分位，附决策建议和因子分解图。
- **联网更新行情**：点击右上角「🔄 更新行情」拉取定时任务抓取的最新报价（见下方准确性说明）。
- **行情库可维护**：支持手动新增/删除条目、JSON 导入导出、恢复默认。

## 定价逻辑（重要）

```
【租赁】
评估租金 = 个人车主月租基准
         × 车源类型(个人1.0/公司1.85)
         × 区域 × 车龄 × 品牌 × 货箱 × 租期 × 司机 × 保险 × 旺季 ...

【二手车 · 双轨】
市场行情法 = 同龄二手车成交价基准
           × 品牌 × 里程 × 排放 × 车况 × 事故 × 保养 × 改装 × 货箱 × 区域 ...
新车折旧法 = 新车购买价 × 分能源残值率(车龄) × 车况类因子
综合估值   = 有新车价：市场法×0.6 + 新车法×0.4
            无新车价：市场法

分能源残值率（3年）：柴油60% / 纯电43% / 混动48% / 氢能45%
```

所有系数集中在 `index.html` 的 `BRAND_FACTOR` / `BODY_FACTOR` / `SOURCE_FACTOR` / `RESIDUAL_CURVE` 四个表中，便于按实际业务调整。评估结果的"因子影响分解"图会逐项展示每个系数的实际作用，"双轨估值交叉验证"面板展示两种方法的对比。

### 三个防偏差机制（避免估值偏离真实行情）

1. **货箱不重复计价**：若命中的行情条目本身就是所选货箱（如飞翼厢式），其报价已含货箱溢价，系统**不再叠加** `BODY_FACTOR` 系数，因子表显示"基准已含该货箱溢价，不重复计价"。只有当基准来自其他货箱时，才按系数换算。
2. **回退优先厢式基准**：无精确货箱行情时，优先取同车型同能源的**厢式**条目作统一基准再换算，避免混合多种货箱的 median 导致专用车厢估值偏低。
3. **样本可靠性 + 异常诊断**：匹配样本少于 3 条时提示区间可能偏窄；当评估价超出行情区间时，自动列出影响最大的 3 个因子（如"车源×1.85、带司机×1.45、旺季×1.22"），方便核对哪项设置不符合实际。

## 联网数据准确性说明（重要）

**联网抓取的报价仅供参考，不直接参与定价计算。** 原因：

- 源网站（卡车之家、天天拍车、58 同城类页面等）常把**新车指导价、二手车成交价、带司机价**混写在文章里，通用程序难以 100% 分辨。
- 抓取脚本会给每条报价标注**口径**（`[租赁价]` / `[二手车价]` / `[新车价]` / `[带司机价]` / `[口径不明]`），请在页面结合标签和来源判断。
- 真正的定价基准来自**人工校准的结构化行情库**（`market-data.json` 的 `data` 字段），口径已明确区分个人车主/租赁公司、车型、货箱、车龄档。
- 因此：想让估值更准，最有效的是在「市场行情库」里补录你掌握的真实成交价，而不是依赖联网抓取。

## 数据客观性说明（供业务部门参考）

结构化行情库共 **47 条**基准，按来源可信度分为三级，每条都带 `conf` 字段，评估结果会自动揭示本次所用基准的等级：

| 等级 | 含义 | 条数 | 使用建议 |
|------|------|------|---------|
| `high` | 平台真实成交价/经销商报价（天天拍车、多麦车、梁山行情等） | 18 | 可直接参考 |
| `mid` | 行业调研折算值（查博士残值率、换电车型、示范城市调研等） | 9 | 参考定位，需结合实车核验 |
| `low` | 行业行情**估算**（非实际成交，按经验区间设定） | 20 | 仅作参考，正式报价务必实车核价 |

- 当本次匹配到 `low` / `mid` 级基准时，结果页会显示黄色警示：**"基准数据可信度"**，明确告知含多少条估算/调研数据。
- **已知局限**：约 43% 的基准为估算值，尤其新能源与冷门车型；这些区间的客观性弱于平台真实成交数据。用于正式对外报价前，建议以实车检测和当地成交价为准。
- 单条行情区间跨度普遍在 1.3~2 倍，个别品类（如二手纯电平板 7~18 万）跨度达 2.6 倍，反映该细分市场样本稀缺、价格离散，使用时需特别注意。

## 安全说明

- 所有来自联网抓取、JSON 导入的文本在渲染前统一 HTML 转义，链接仅允许 `https/http` 协议，杜绝存储型 XSS 与 `javascript:` 注入。
- 数据导入会做结构校验，自动过滤空值、非法价格、注入字段，并在提示中告知过滤数量。
- 抓取脚本启用 HTTPS 证书校验、仅允许公开域名，防止中间人篡改与内网探测；单个源失败自动跳过，不影响整体。
- 本项目为纯静态页面，无后端、无账号、无用户数据上传，不收集任何使用者信息。

## 部署到 GitHub（约 5 分钟）

### 1. 创建仓库并上传

在 GitHub 新建一个仓库（建议公开，便于 Pages 访问），把本目录所有文件上传（含 `.github` 隐藏目录）。

如果用命令行：

```bash
cd 本项目目录
git init
git add .
git commit -m "init: 货车价格评估系统"
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git branch -M main
git push -u origin main
```

### 2. 开启 GitHub Pages

1. 进入仓库 → **Settings** → 左侧 **Pages**
2. **Build and deployment** → Source 选择 **Deploy from a branch**
3. Branch 选 **main**，目录选 **/(root)** → **Save**
4. 等待约 1 分钟，访问 `https://<你的用户名>.github.io/<仓库名>/` 即可

> 如果希望用独立域名或根路径访问，可把仓库改名为 `<你的用户名>.github.io`，地址就是 `https://<你的用户名>.github.io/`。

### 3. 启用行情自动更新

workflow 已经配置好，push 到仓库后会自动生效：

- **自动**：每周一、周四北京时间 09:00 抓取一次最新行情并提交
- **手动**：仓库 → **Actions** → 左侧选「更新货车市场行情」→ **Run workflow** → 立即抓取

抓取结果写入 `market-data.json`，页面点击「🔄 更新行情」即可读取。

### 珠三角重点覆盖

抓取策略对区域做了差异化配置（`scraper.py` 的 `SOURCES`）：

- **珠三角**（广州/深圳/佛山/东莞等）：配置了 6 个专属行情源，覆盖带司机租赁、纯租车、车主直租、二手成交，每个源最多抓 **8 条**（其他区域仍为 3 条），并优先展示。
- **其他区域**：抓取源与配额保持不变。
- 每条抓取信号带 `region` 标签（`珠三角` / `全国`），页面「联网抓取」区提供 `全部 / 📍珠三角（重点） / 其他区域` 三个筛选按钮，珠三角条目带红色 📍 标签并置顶。
- 区域信号总量上限提高到 60 条，确保珠三角增量不会被其他源挤出。

> 说明：珠三角多抓的数据同样**只作参考、不参与定价计算**（口径混杂问题见上文）。若要让珠三角估值更准，最有效的是把当地真实成交价补录进「市场行情库」。

> 注意：GitHub Pages 默认每次 commit 后重新部署，行情更新后页面会自动同步新数据。

## 更新行情的两种方式

| 方式 | 适用场景 | 操作 |
|------|---------|------|
| 点击页面「🔄 更新行情」 | 想读取最新的抓取结果 | 需通过 GitHub Pages 或本地 HTTP 服务访问（见下） |
| 手动编辑 / 导入 JSON | 自己掌握了一手报价 | 页面「📊 市场行情库」中增删，或导入导出的 JSON |

> **为什么本地双击 HTML 时「更新行情」可能失败？**
> 浏览器的 `file://` 协议因安全策略无法用 fetch 读取本地 JSON。本地调试时请在目录下起一个静态服务：
> ```bash
> python3 -m http.server 8000
> ```
> 然后访问 `http://localhost:8000/`。部署到 GitHub Pages 后无此问题。

## 数据来源与口径说明

- 初始行情为联网调研采集的公开市场快照（卡车之家、天天拍车、百度爱采购、梁山/高安等市场行情、行业调研报告等），标注来源与日期。
- **`data`（定价基准）**：人工校准的结构化行情，避免网页误解析把"新车指导价"当成"二手车成交价"。
- **`signals`（最新报价）**：抓取脚本从行情源提取的含价格原文，供决策参考，不直接参与定价计算。
- 二手车估值随市场波动，结果仅供参考，实际成交以车况检测和当地市场为准。

## 自定义行情源

编辑 `scraper.py` 顶部的 `SOURCES` 列表即可增删抓取源：

```python
SOURCES = [
    {"name": "源名称", "url": "https://...", "keys": ["二手", "万"]},
    ...
]
```

`keys` 为命中关键词，只有同时包含价格数字和任一关键词的句子才会被提取。
